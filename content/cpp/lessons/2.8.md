Real programs are split over many source files so each one stays small and focused.

## How it works

Each `.cpp` file is compiled **separately** into an *object file*. Then the **linker** combines all object files (and library code) into one executable.

```
main.cpp  --compile-->  main.o  \
                                  >--link-->  program
add.cpp   --compile-->  add.o   /
```

## Example

`add.cpp` defines a function:

```cpp
int add(int x, int y)
{
    return x + y;
}
```

`main.cpp` uses it, so it needs a forward declaration. When compiling `main.cpp` the compiler only needs to know that `add` exists and what its types are:

```cpp
#include <iostream>

int add(int x, int y);      // declaration only

int main()
{
    std::cout << add(2, 3);
    return 0;
}
```

The linker later connects the call in `main.o` to the definition in `add.o`.

## Two kinds of errors

- **Compile error:** a problem inside one file (syntax error, undeclared name).
- **Link error:** every file compiled, but the pieces do not fit: a function is declared but never defined (*undefined reference*), or defined in two files (*multiple definition*).

> [!note] In an IDE you add each `.cpp` file to the same project so all of them are built and linked together. Never `#include` a `.cpp` file to share code; the next lessons show the right way with headers.

## Recap

- Source files are compiled separately, then the linker joins them.
- Each file needs forward declarations for functions defined elsewhere.
- Compile errors happen per file; link errors happen when pieces do not match up.
- Add all `.cpp` files to the project, and do not `#include` them.
