An **uninitialized variable** is one that has been defined but never given a value:

```cpp
int x;                // no value yet
std::cout << x;       // reads leftover bits: undefined behavior
```

C++ does not clear memory for you. The variable simply occupies a spot in memory that still holds whatever bits were left there before, so reading it gives an unpredictable value.

## Undefined behavior

**Undefined behavior (UB)** is what you get when you write code that the language gives no rules for. Anything can happen:

- a random-looking value,
- the same wrong value every run,
- a crash,
- or the worst case: it appears to work, and breaks later when you change something unrelated (the compiler, the operating system, an unrelated line).

Other common sources of UB are dividing an integer by zero and using an index outside a string or array.

> [!warn] "It worked when I ran it" proves nothing about code with undefined behavior. Never rely on it.

In this app, the built-in C++ interpreter stops with an error when you read an uninitialized variable, so you can see exactly where the mistake is.

## How to avoid it

- Initialize variables when you define them: `int x{};` or `int x{ 5 };`.
- If you have to define a variable first, make sure it is assigned before its first read. Reading into it with `std::cin >> x;` counts as assigning it.

```cpp
int x;
std::cin >> x;      // fine: x gets a value before it is used
std::cout << x;
```

## A related idea: implementation-defined behavior

Some things are decided by the compiler and platform, such as how many bytes an `int` occupies (usually 4). This is **implementation-defined**: it can differ between systems, but each compiler must stay consistent and document its choice. That makes it very different from undefined behavior.

## Recap

- An uninitialized variable holds an unpredictable leftover value.
- Using it is undefined behavior: the program may do anything.
- Avoid UB by initializing variables, or assigning before the first read.
- Implementation-defined behavior is consistent per compiler; undefined behavior is not.
