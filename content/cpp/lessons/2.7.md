The compiler reads your file from top to bottom. If you call a function **before** the compiler has seen it, you get an error:

```cpp
int main()
{
    std::cout << multiply(6, 7);   // error: multiply was not declared
    return 0;
}

int multiply(int x, int y) { return x * y; }
```

## Forward declarations

You could reorder the code, but that is not always possible (two functions may call each other). The fix is a **forward declaration**: a line that tells the compiler a function exists, without giving its body.

```cpp
int multiply(int x, int y);    // declaration (also called a prototype)

int main()
{
    std::cout << multiply(6, 7);   // fine now
    return 0;
}

int multiply(int x, int y)     // definition
{
    return x * y;
}
```

A declaration consists of the return type, name, parameter types and a **semicolon**. Parameter names are optional there: `int multiply(int, int);` works too, but keeping the names documents the code.

## Declaration vs definition

- A **declaration** tells the compiler a name exists and what type it has.
- A **definition** actually creates it: the function body, or a variable's storage.
- Every definition is also a declaration.

## One Definition Rule

- A function (or variable) may be **defined only once** in the program.
- It may be **declared** as many times as you like.

> [!warn] If you declare a function and call it but never define it anywhere, the compiler is happy but the **linker** fails with an "undefined reference" error.

## Recap

- Functions must be declared before they are called.
- A forward declaration is the function header followed by `;`.
- Declarations introduce names; definitions create them. Define once, declare as often as needed.
- A declared but undefined function causes a linker error.
