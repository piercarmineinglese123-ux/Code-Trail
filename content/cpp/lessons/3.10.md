The best bug is the one that never happens. These habits catch problems early, when they are cheapest to fix.

## Writing safer code

- **Keep functions short** and focused, with a clear purpose. Small pieces are easy to understand and test.
- **Initialize every variable** when you define it.
- **Avoid unnecessary cleverness.** Straightforward code has fewer places to hide mistakes.
- **Keep scopes small**, defining variables near their first use.
- **Do not repeat yourself.** One copy of a rule means one place to get it right.
- Prefer clear names over comments that explain confusing ones.

## Letting tools help

- **Turn on compiler warnings** (for GCC/Clang: `-Wall -Wextra -pedantic`) and fix every one. Many bugs are reported as warnings.
- Consider **treating warnings as errors** so none are ignored.
- **Static analysis tools** read your code without running it and flag likely mistakes.
- Use **version control** (such as git), so you can compare against the last working version when something breaks.

## Test early and often

- Test each function as soon as you write it, with normal input and **edge cases** (zero, negative numbers, the largest and smallest values, empty input).
- Re-run old tests after each change to catch regressions.
- Keep a few small programs or test cases that reproduce past bugs.

## Check your assumptions

If your code relies on something being true (a number is positive, a divisor is non-zero), verify it or handle the case explicitly. Later lessons introduce error handling and assertions, which turn silent wrong behavior into a clear error.

## Recap

- Prevent bugs: short functions, initialized variables, simple code, small scopes.
- Enable compiler warnings and fix them; use static analysis and version control.
- Test every function early, including edge cases, and re-test after changes.
- Make assumptions explicit by checking them.
