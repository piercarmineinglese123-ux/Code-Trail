A **comment** is text written for humans. The compiler ignores it completely.

## Two kinds of comment

```cpp
// A single-line comment runs to the end of the line.
int x{ 5 };   // it can also follow some code

/* A multi-line comment
   can span as many lines
   as you like. */
```

Multi-line comments **cannot be nested**. The first `*/` ends the comment, no matter how many `/*` came before it:

```cpp
/* outer /* inner */ this part is NOT a comment */
```

Here the words after the first `*/` are treated as code, which causes an error.

## What good comments say

- At the top of a file or function: *what* it does, in plain words.
- Inside a function: *how* it works, when that is not obvious from the code.
- On a statement: *why* it is there. Do not just repeat what the code says.

```cpp
x = x + 1;   // Bad: add one to x
x = x + 1;   // Good: skip the header row
```

Write comments for a reader who does not know what you were thinking, which usually means yourself in three months.

## Commenting out code

Putting `//` in front of a statement disables it without deleting it. This is handy for testing:

```cpp
std::cout << "A";
// std::cout << "B";   // never runs
std::cout << "C";      // prints: AC
```

> [!tip] Do not leave big blocks of commented-out code in finished programs. Version control remembers old code for you.

## Recap

- Comments are ignored by the compiler and exist for humans.
- `//` comments to the end of the line; `/* ... */` can span several lines but cannot be nested.
- Comment the why, not the obvious what.
- Commenting out a statement temporarily disables it.
