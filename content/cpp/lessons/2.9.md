## Naming collisions

Two different things cannot share the same name in the same scope. If they do, you get a **naming collision**:

```cpp
// a.cpp
int value() { return 1; }

// b.cpp
int value() { return 2; }   // linker error: value is defined twice
```

In small programs this is rare. In big ones, and when you combine code from several libraries, it becomes a real risk.

## Namespaces

A **namespace** is a named region that gives its contents their own scope. Names in different namespaces do not collide.

```cpp
namespace Math
{
    int value() { return 1; }
}

namespace Game
{
    int value() { return 2; }
}
```

## The scope resolution operator `::`

To reach a name inside a namespace, write the namespace, `::`, then the name:

```cpp
std::cout << Math::value();   // 1
std::cout << Game::value();   // 2
```

You have already used this: `std::cout` means "`cout`, which lives in the namespace `std`". **`std`** holds the entire C++ standard library.

## The global namespace

Names declared outside any namespace belong to the **global namespace**. `main` lives there. A name with a leading `::` (like `::value`) explicitly means the global one.

## `using namespace`

`using namespace std;` lets you drop the `std::` prefix, but it brings *every* standard name into your scope, which can reintroduce collisions.

> [!tip] Prefer writing `std::` explicitly. It is a few extra characters, and it removes any doubt about where a name comes from.

## Recap

- A naming collision happens when two entities share a name in the same scope.
- Namespaces create separate scopes; `::` selects a name from one.
- The standard library lives in `std`; non-namespaced names are in the global namespace.
- Avoid `using namespace std;` in real code.
