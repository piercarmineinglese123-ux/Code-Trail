Before writing code for a bigger program, spend a few minutes designing it. A good design saves hours of rewriting.

## A simple process

1. **Define the goal.** One sentence: what should the user get out of this program?
2. **List the requirements.** What must it do, and what is explicitly out of scope? Keep it small; you can add features later.
3. **Break it into tasks.** Split the goal into steps, and split big steps into smaller ones until each is a job one function can do (*top-down design*).
4. **Order the tasks.** Decide the sequence they run in, and what data passes between them.
5. **Implement and test step by step**, starting with `main` as an outline.

## Example: a tiny "larger of two" tool

Goal: read two integers and say which is larger.

Tasks: read a number, compare two numbers, print the result.

Outline written first, in `main`:

```cpp
int main()
{
    int a{ readNumber() };
    int b{ readNumber() };
    printResult(larger(a, b));
    return 0;
}
```

Each named function is one small task. Now write them one at a time, running the program after each, instead of all at once.

## Tips

- Prefer simple, readable solutions; clever code is hard to change.
- Write functions that take inputs and **return** results; keep input and output in a few dedicated places.
- Plan for the future a little (names, structure), but do not build features nobody asked for.
- Expect to revise the design as you learn more; that is normal.

## Recap

- Design before coding: goal, requirements, tasks, order.
- Break big problems into small tasks, each one function (top-down).
- Write `main` as an outline of function calls, then fill in the functions one by one, testing as you go.
- Keep it simple and expect to refine it.
