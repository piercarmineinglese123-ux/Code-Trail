Stepping line by line is slow when the problem is far into the program. Two features let you jump ahead.

## Run to cursor

Place the text cursor on a line and choose **Run to cursor**. The program runs at full speed and pauses just before that line, as long as execution gets there.

## Breakpoints

A **breakpoint** is a marker on a line, usually set by clicking in the margin or pressing a key. Whenever execution reaches that line, the debugger **pauses** before running it. Breakpoints stay until you remove them, even across runs.

Typical workflow:

1. Set a breakpoint on or just before the suspicious code.
2. Start debugging. The program runs until it hits the breakpoint.
3. Inspect values and step through the interesting part.
4. **Continue** to run on until the next breakpoint, or until the program ends.

## Useful commands

- **Start / Run with debugging**: launches the program under the debugger.
- **Continue**: resume normal running until the next breakpoint.
- **Stop**: end the debugging session.
- **Restart**: stop and start over.

## Bonus tools

- A **conditional breakpoint** only pauses when an expression is true (for example `i == 500`). Perfect for loops that run thousands of times.
- Breakpoints can be **disabled** without deleting them.

> [!warn] Some IDEs allow "set next statement", which makes execution skip or repeat code. It is powerful but can leave variables in states the real program never reaches, so use it with care.

## Recap

- Run to cursor runs until a chosen line.
- A breakpoint pauses the program whenever execution reaches its line; Continue resumes.
- Conditional breakpoints pause only when a condition is true.
