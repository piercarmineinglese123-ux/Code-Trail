Forward-declaring every function in every file that uses it quickly becomes tedious and error-prone. **Header files** solve this: put the declarations in one `.h` file, and `#include` it wherever they are needed.

## A header and its source file

`add.h` (declarations only):

```cpp
int add(int x, int y);
```

`add.cpp` (the definition). It includes its own header:

```cpp
#include "add.h"

int add(int x, int y)
{
    return x + y;
}
```

`main.cpp` (a user of the function):

```cpp
#include "add.h"
#include <iostream>

int main()
{
    std::cout << add(2, 3);
    return 0;
}
```

If the declaration ever has to change, you edit it in one place.

## `"quotes"` versus `<angle brackets>`

- `#include "add.h"` looks in your own project first. Use it for **your** headers.
- `#include <iostream>` searches the compiler's standard locations. Use it for the **standard library** and installed libraries.

Standard library headers have no `.h`: write `<iostream>`, not `<iostream.h>`.

## Why the source file includes its own header

If `add.cpp` includes `add.h`, the compiler checks that the declaration and the definition agree. A mismatch becomes a compile error instead of a confusing link error.

## Guidelines

- Put **declarations** in headers and **definitions** in `.cpp` files.
- Never `#include` a `.cpp` file.
- Include every header whose declarations you use; do not rely on another header happening to include it.

> [!note] Headers may legitimately contain a few definitions (such as constants and certain special functions), which later lessons cover. For ordinary functions, keep the body in the `.cpp`.

## Recap

- A header holds shared declarations; `#include` pastes them where needed.
- Use quotes for your headers and angle brackets for standard ones.
- A source file should include its own header to catch mismatches.
- Declarations go in headers, definitions in source files; never include `.cpp` files.
