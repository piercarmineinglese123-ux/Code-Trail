When a program calls a function, the computer must remember where to continue once that function returns. It keeps this record on the **call stack**.

## What it is

The **call stack** is a list of all the functions that are currently active (called but not yet returned). Each entry is a **stack frame**, holding that call's local variables and its return location.

Take this program:

```cpp
void c() { /* breakpoint here */ }
void b() { c(); }
void a() { b(); }
int main() { a(); return 0; }
```

While paused inside `c`, the call stack looks like this (most recent call on top):

```
c()
b()
a()
main()
```

- `main` is at the bottom: it was called first (by the runtime).
- Each function called adds a frame on top.
- When a function returns, its frame is removed.

## The debugger's call stack window

Debuggers show this list for you. It answers "**how did I get here?**" Clicking a frame displays that function's code and its local variables at the point of the call. This is especially valuable when a bug appears in a helper function that is called from many places: the stack shows which caller passed the bad value.

## Infinite recursion

A function that keeps calling itself without stopping adds a frame each time until memory for the stack runs out. The result is a **stack overflow**, and the program crashes. The call stack window would show the same function repeated thousands of times.

## Recap

- The call stack lists the functions currently running; each entry is a stack frame.
- The most recent call is on top; `main` is at the bottom.
- The debugger's call stack view shows how execution reached the current line, and lets you inspect each caller.
- Endless recursion overflows the stack.
