You do not need special tools to start debugging. These tactics work with just a compiler.

## 1. Comment out code

Disable a section with `//` or `/* */` and see whether the problem changes. If it disappears, the cause is in the part you removed. It also shrinks the area you have to think about.

## 2. Check the flow

Make sure the function you are debugging is actually called, and in the order you expect, by printing its name:

```cpp
int add(int x, int y)
{
    std::cout << "add() called\n";
    return x + y;
}
```

## 3. Print values

Print the inputs, intermediate results and outputs, and compare them against what you expect:

```cpp
int sum{ 0 };
for (int i{ 1 }; i < n; ++i)
{
    sum += i;
    std::cout << "i=" << i << " sum=" << sum << '\n';   // debug
}
```

Seeing `i` stop one short of `n` reveals the bug at once.

## Tips

- Give debug lines a recognizable look, such as a `DEBUG:` prefix, so they are easy to find and delete.
- Do not indent them like real code; being visually different makes it harder to forget them.
- Print *before* the suspicious line, as well as after. A crash can swallow output that came later.
- **Remove or disable** debug output before you finish.

## Downsides

- It clutters the code and the output.
- Each experiment means editing and recompiling.
- You may accidentally leave a statement behind, or change the behavior while adding it.

Later lessons show cleaner options, including conditional compilation and a real debugger.

## Recap

- Comment out code to narrow down the problem.
- Print function names to verify the program flow.
- Print variable values to compare reality against your expectations.
- Mark debug statements clearly and remove them when done.
