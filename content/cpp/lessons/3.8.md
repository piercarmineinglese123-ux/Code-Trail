Pausing is only useful if you can look at the data. Debuggers let you inspect variables while the program is paused.

## Seeing values

- **Hover** the mouse over a variable in the editor to see its current value.
- The **Locals** (or *Autos*) window lists the variables in the current scope together with their values. Values that just changed are usually highlighted.
- The **Watch** window holds expressions you choose, and shows their value every time execution pauses.

## Watch expressions

A watch is not limited to single variables. You can enter expressions such as:

```
sum
i * 2
total / count
```

The debugger re-evaluates them at each pause, so you can see exactly how a value evolves as you step, and notice the instant it becomes wrong.

## What to look for

- A value that is not what you expected, which tells you the bug is at or before this point.
- A variable that never changes inside a loop.
- Garbage-looking numbers (huge, negative, or strange): usually an **uninitialized variable**.
- Variables from other scopes appearing or disappearing as you step in and out of functions.

## Changing values

Most debuggers also let you edit a variable's value while paused. This is handy for testing a hypothesis ("what if `count` were 0 here?") without editing and recompiling.

> [!note] A watch on a variable that is out of scope shows an error or "not available". That is normal; it comes back when execution returns to a scope where the name exists.

## Recap

- Hover, Locals/Autos and Watch windows show variable values while paused.
- Watch accepts expressions and re-evaluates them at every pause.
- Look for unexpected values, unchanging variables and garbage from uninitialized memory.
- You can often edit a value to test a theory quickly.
