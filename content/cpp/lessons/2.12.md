Headers can include other headers, so the same header may reach a file by two routes. If it contains a definition, the compiler sees that definition twice in one translation unit and reports a redefinition error.

```cpp
// square.h (contains a definition on purpose)
int getSquareSides() { return 4; }

// wave.h
#include "square.h"

// main.cpp
#include "square.h"
#include "wave.h"     // brings square.h in a second time: error
```

## Header guards

A **header guard** makes a header include its contents only the first time. It uses conditional compilation:

```cpp
#ifndef SQUARE_H
#define SQUARE_H

// contents of the header go here

#endif
```

How it works:

1. First inclusion: `SQUARE_H` is not defined, so the code runs through `#define SQUARE_H` and the contents are kept.
2. Second inclusion: `SQUARE_H` is already defined, so everything up to `#endif` is skipped.

Rules for the name:

- Make it **unique** to the file. A common pattern is the file name in capitals, optionally with the project name: `MYPROJECT_SQUARE_H`.
- Two headers with the same guard name would silently hide each other.

## `#pragma once`

Most compilers also accept a one-line alternative:

```cpp
#pragma once
```

It is shorter and cannot be mistyped, but it is not part of the official C++ standard. Header guards work everywhere.

## What guards do not do

They stop a header from being included twice **within one file**. They do not stop it being included once in *each* of several `.cpp` files. So a function **defined** in a header still breaks the One Definition Rule across files, which is one more reason to keep definitions out of headers.

## Recap

- Including a header twice in one file can cause redefinition errors.
- A header guard (`#ifndef` / `#define` / `#endif`) makes later inclusions empty.
- Use a unique guard name per header; `#pragma once` is a common shortcut.
- Guards work per translation unit; they do not make header definitions safe across several source files.
