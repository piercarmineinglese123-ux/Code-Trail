Programming mistakes fall into two broad families.

## Syntax errors

A **syntax error** breaks the grammar rules of C++: a missing semicolon, an unmatched brace, a misspelled keyword. The compiler detects these and refuses to build the program, usually pointing at a line number.

```cpp
int x{ 5 }            // error: expected ';'
std::cout << x;
```

> [!tip] The reported line is where the compiler *noticed* the problem. For a missing semicolon, that is often the line **after** the mistake. Always read the first error first; later ones are often side effects of it.

## Semantic errors

A **semantic error** is code that is grammatically valid but does the wrong thing. The compiler accepts it, so you only find out by running the program.

```cpp
int average{ a + b / 2 };     // intended (a + b) / 2: wrong because of operator order
for (int i{ 1 }; i < n; ++i)  // intended i <= n: skips the last value
```

Common causes are logic mistakes, wrong operators, misunderstood requirements, and undefined behavior such as using an uninitialized variable.

## Reading compiler output

- Fix errors from the top down, recompiling often.
- Warnings are not errors, but they usually point to real problems. Treat them as something to fix, not to ignore.
- Search the exact message text if it is unfamiliar.

## Recap

- Syntax errors violate the grammar; the compiler finds them.
- Semantic errors compile but behave wrongly; you find them by testing and debugging.
- Fix the first compiler error first, and take warnings seriously.
