Functions are the main tool for keeping programs manageable. Here is why they pay off.

## Benefits

- **Organization.** A long program becomes a few short, named steps. `main` can read like an outline.
- **Reusability.** Write once, call from many places.
- **Easier fixes.** If a rule changes, you change it in one function instead of hunting for copies.
- **Testing.** A small function can be tested on its own with known inputs.
- **Abstraction.** The caller only needs to know *what* a function does, not *how*.

## Don't repeat yourself

Duplicated code is a bug waiting to happen: fix it in one place and forget the other. If you paste the same lines twice, make them a function.

```cpp
// repeated
std::cout << "Total: " << a + b << '\n';
std::cout << "Total: " << c + d << '\n';

// better
void printTotal(int x, int y) { std::cout << "Total: " << x + y << '\n'; }
printTotal(a, b);
printTotal(c, d);
```

## Writing good functions

- **One job each.** If you need "and" to describe it, consider splitting it.
- **A clear name**, usually a verb: `readNumber`, `printReport`, `isEven`.
- **Short.** When a function no longer fits on a screen, look for pieces to move out.
- **Few parameters.** Many parameters usually mean the function does too much.
- Prefer functions that *compute and return* a value over ones that read input and print inside, because they are easier to reuse and test.

## Recap

- Functions give organization, reuse, easier changes, testing and abstraction.
- Don't repeat yourself: turn duplicated code into a function.
- Give each function one job, a verb name, and keep it short.
