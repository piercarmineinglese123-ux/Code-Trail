A **debugger** is a program that runs your program under your control. Instead of adding print statements, you can pause execution and watch what happens. Every IDE (Visual Studio, Code::Blocks, CLion, VS Code) includes one, and the same ideas apply in all of them.

## Stepping

**Stepping** means running a program one statement at a time. While it is paused, an arrow or highlight, the **execution marker**, shows the statement that will run **next** (it has not run yet).

## The stepping commands

| Command | What it does |
|---|---|
| **Step into** | Run the next statement. If it is a function call, jump inside the function and pause on its first line. |
| **Step over** | Run the next statement completely. A function call runs in one go and you pause on the line after it. |
| **Step out** | Run until the current function returns, then pause in the caller. |

Choosing between them:

- Use **step over** for calls you trust (like `std::cout`).
- Use **step into** for functions you want to inspect.
- If you stepped into a function by mistake, **step out**.

## Why it helps

You see the real order of execution, which branch an `if` took, and how many times a loop repeats, without changing the source code at all.

> [!tip] Step into a call to a library function such as `std::cout <<` can drop you into the standard library's code. Step out, and use step over next time.

## Recap

- A debugger lets you pause and control a running program.
- The execution marker points at the next statement to run.
- Step into enters function calls, step over runs them whole, step out finishes the current function.
