Writing a program is easier when you design it before typing it. Here is a simple process that works for small and big programs alike.

## Four steps

1. **Define the problem.** State in one or two sentences what the program must do. Example: "Ask for a number of minutes and show it as hours and minutes."
2. **Plan the solution.** Work out how you would solve it by hand. For minutes: hours = minutes / 60 (whole part), remainder = minutes % 60.
3. **Write it in small steps.** Get a tiny version running, then add one piece at a time.
4. **Test.** Run it with several inputs, including edge cases such as `0` or exact multiples.

## Build it incrementally

Start with only the skeleton and confirm it compiles:

```cpp
#include <iostream>

int main()
{
    return 0;
}
```

Add input, and print it back to check it was read correctly:

```cpp
int minutes{};
std::cin >> minutes;
std::cout << minutes << '\n';   // temporary check
```

Then add the calculation:

```cpp
std::cout << minutes / 60 << " h " << minutes % 60 << " min\n";
```

At each step the program works, so when something breaks you know it was the last thing you added.

> [!tip] Keep each step small enough that you can predict the exact output before you run it. If the result surprises you, you have found a misunderstanding early.

## Typical beginner traps

- Writing everything at once, then facing a wall of errors.
- Forgetting to test unusual inputs.
- Not reading the problem again at the end: does the output match what was asked, character for character?

## Recap

- Define the problem, plan the solution, write in small steps, then test.
- Get a minimal program compiling first, and add one feature at a time.
- Print intermediate values to confirm each step, then remove the extra output.
- Test normal and edge-case inputs.
